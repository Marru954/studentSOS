## Workspace layout

Git repo at this root; it holds the product plus repo-level tooling and recon notes:

- **`studentos/`** — the main product: "University Student OS", a Next.js App Router app. Almost all work happens here.
- **`scripts/`** (`safe-merge.sh`, `verified-endpoints.txt`), **`docs/`** + **`fixtures/`** (Cineca/GOMP recon material) and the loose `_recon_*` / `_review_*` notes — repo-level support, not product code. Run all commands **inside `studentos/`**, not from this root.

## ⚠️ Next.js version caveat (read first)

`studentos/AGENTS.md` warns: this is **Next.js 16.3.6 (Turbopack), React 19, Tailwind v4** — APIs differ from training data. Since 16.3, `next dev` rewrites the managed `<!-- BEGIN:nextjs-agent-rules -->` block in `studentos/AGENTS.md` whenever its text changes: commit that diff with your work (reverting it only makes it come back). **Before writing any Next/React code, read the relevant guide under `studentos/node_modules/next/dist/docs/`.** Concretely confirmed differences already hit: `cookies()` is **async**; Route Handlers set cookies on the returned `NextResponse`; the `react-hooks` ESLint rules reject `setState` in a mount effect (use `useSyncExternalStore`, see `src/lib/hooks/useNowMinute.ts`) and reject ref writes during render.

## Permanent rules (apply to every task — never need restating in a prompt)

- **Never edit:** `src/lib/storage/db.ts` (IndexedDB schema), existing files in `tests/`, `package.json`, `scripts/`. If a task seems to require a schema bump, find another way; if truly unavoidable, stop and flag rather than change it silently.
- **Never edit the sync core:** `src/lib/sync/adapters/easyacademy.ts`, `src/lib/sync/engine.ts`.
- **Never invent EasyAcademy `scuola`/`corso`/`anno2` codes.** Use only codes confirmed by a real GET on `combo.php` (+ POST `grid_call.php`/`test_call.php` returning `celle`/`Appelli`). Unverifiable or empty → `liveSources: false` / leave the degree out of `livePrograms`, with the reason in a comment. Wrong data is worse than none.
- **Green before commit:** `npm run build`, `npm test`, `tsc --noEmit`, `npm run lint` all pass first. One commit per completed objective/feature.
- **No new npm dependency** unless the user explicitly asks.
- **Local-first is the product, not a fallback.** User data lives in IndexedDB, on the device; the app works **fully** with no account. The Supabase email+password login is **optional** — backup/multi-device for those who want it, never required. The data-security wall for cloud rows is **Supabase RLS**, not local encryption. **Copy/UI rule:** never promise the cloud or sync as default behaviour — the default is local, sync is an opt-in extra. (This rule exists because the copy has repeatedly contradicted the footer by promising "dati su ogni dispositivo".)
- **Central actions never fail silently.** Core product actions (e.g. registering a voto in the Libretto) must surface validation **inline next to the field**, mark required fields, and announce errors for a11y — never a single message at the bottom of the form / below the fold.
- **Design language is fixed:** glass, aurora, Bricolage Grotesque, Tailwind v4, CSS-variable tokens — reskin via the `@theme` var blocks, never per-component.
- **Accessibility on every new component:** `aria-label`, `sr-only`, keyboard-reachable.
- **UI copy is always Italian.**
- **`"use client"` only where strictly needed** (state/effects/browser APIs) — components stay server by default.
- **UI bug? Root cause is mandatory, in this order:** (1) reproduce it in the browser as a real signed-in user, (2) write down the root cause explicitly — not the symptoms, (3) only then implement the fix, (4) reopen Chrome signed-in and verify visually, (5) commit only after the visual check. Never accept "fixed" without having watched the correction work on real data in the browser.
- **Never fix symptoms.** If a bug is reported more than once, the previous fix treated symptoms, not the cause. Before every fix ask: "what single root cause explains ALL the reported cases?" — fix only that.
- **Multi-ateneo QA via script, not repeated onboarding.** To check data across atenei, read IndexedDB/Supabase directly with a JS snippet in the browser console or a Node script. Do manual onboarding only for the first test ateneo.


Tests use `node:test` + `tsx` + `fake-indexeddb` (no Jest/Vitest). The suite is **48 explicit `tests/*.test.ts` files** listed one-by-one in the `test` script — it is **NOT a glob**, so a new test file runs only after you add it to `package.json` (the one file you're otherwise told never to edit; adding a test invocation is the sanctioned exception). It now covers the pure domain modules **plus the API routes** (`api-sync`, `api-assistente`, `api-import-pdf`, `api-sync-delphi`, `api-health`, `api-alerts`) and the security guard (`validateUrl`, `guard`).

**Browser availability is session-dependent.** When a Playwright MCP browser is attached (and a `next dev` server is running), verify UI as a real signed-in user — that is the preferred path and `playwright.config.ts` wires E2E `**/*.spec.ts` against `http://localhost:3000`. In a **headless** environment with no browser, fall back to `scripts/audit-render.ts` (SSR-render components to static HTML for markup/a11y audits) and compute WCAG contrast ratios from the compiled CSS in `.next/static`. The Delphi PDF import has two extra helpers that run pdfjs headless in Node: `scripts/dump-pdf-text.ts <file.pdf>` (dump extracted text to a fixture) and `scripts/verify-delphi-pdf.ts <file.pdf>` (end-to-end parse check).

## Git workflow

- **Il lavoro nasce sempre su un branch dedicato, mai direttamente su `main`.** `main` è protetto: ci si arriva **solo** via `./scripts/safe-merge.sh`. Niente `git push origin main` diretto, niente merge a mano.
- Commit subject: `<ateneo|feature|fix|docs>: <short description in Italian>` (e.g. `fix: calendario appelli filtrato per anno`).
- **Merge su `main` solo a gate verde:** dal branch di lavoro lancia lo script alla **root del repo**, `<root>/scripts/safe-merge.sh` (repo-aware, gira il gate dentro `studentos/`). Esegue build + test + tsc --noEmit + lint **più i muri #4/#5**: nessun URL/codice EasyAcademy non presente in `scripts/verified-endpoints.txt` (override una-tantum `ALLOW_UNVERIFIED_URLS=1`) e nessuna dipendenza npm nuova (override `ALLOW_NEW_DEPS=1`); `DRY_RUN=1` per provare senza mergiare. Solo se tutto passa fa il merge, crea un tag `rollback/<data-ora>` sullo stato di `main` precedente al merge e lo pusha su origin insieme a `main` (fast-forward se possibile, altrimenti merge commit). Il wrapper `studentos/scripts/safe-merge.sh` e gli hook PreToolUse dei muri #4/#5 sono stati rimossi dalla PR #41 (regole v2): i muri #4/#5 vivono solo dentro lo script, ripristinato il 2026-09-26 su scelta esplicita dell'utente.
- **Auto-merge (`./scripts/safe-merge.sh --auto`, deciso il 2026-09-26):** stesso flusso ma senza fermarsi ad aspettare l'utente — gate verde + muri #4/#5 + nessun file sensibile → tag di rollback → merge → push; gate rosso = stop, nessun tag/merge. **Eccezione non rimovibile senza nuova autorizzazione esplicita:** se il branch tocca preset/config EasyAcademy o il modulo di sync verso le università (o le guardie del merge stesse: lo script, `.claude/settings.json`, `studentos/scripts/hooks/`) esce con codice **10** ("AUTO-MERGE FERMATO") anche a gate verde: mostra all'utente i file elencati e rilancia **senza** `--auto` solo dopo un sì esplicito in chat. A ogni corsa scrive il riepilogo in `studentos/docs/stato/LAST_SESSION_SUMMARY.md` (gitignored). Dettagli e limiti del rilevamento: STATO.md, sessione 2026-09-26 (sexies); stato per ateneo: `studentos/docs/stato/ATENEI_TRACKING.md`.
- Lo script **fallisce in modo esplicito** se sei su `main`, se il working tree è sporco, se `main` locale diverge da `origin/main`, o se il gate non è verde: nessun merge su stato incoerente. Rollback: `git reset --hard rollback/<data-ora>`.
- **Tight sessions:** max 5–6 objectives per session. Quando un blocco è chiuso, `safe-merge.sh` poi apri una sessione fresca. Don't compact — a clean restart beats a compacted context.
- **Aggiorna `docs/stato/STATO.md` dopo ogni sessione:** prima del merge, riscrivi STATO.md con i task completati oggi, quelli in sospeso e i prossimi obiettivi. Data in cima al file.
- **Autonomia (regola permanente, richiesta dall'utente il 2026-09-25): i passi di routine li fa Claude, senza che l'utente li chieda.** Dopo ogni merge su `main`, nella stessa risposta: (1) ripristina i checkout (root di nuovo su `main`, il proprio worktree sul proprio branch); (2) `git fetch` e controllo **di sola lettura** dei conflitti tra il lavoro appena mergiato e **ogni altro branch/worktree attivo** (`git merge-tree --write-tree --name-only main <branch>`), riportando file in conflitto **e** sovrapposizioni semantiche — senza risolvere il branch di qualcun altro; (3) cancella i propri branch locali già mergiati; (4) aggiorna STATO.md. Si chiede conferma solo per azioni distruttive su cose non proprie (altri worktree, branch non mergiati, force push).
- **Merge da worktree** (`main` è aperto nel checkout principale, quindi `safe-merge.sh` da lì non gira): `git -C <root> switch --detach` (root pulito) → `./scripts/safe-merge.sh` dal branch di lavoro, con `GIT_AUTHOR_*`/`GIT_COMMITTER_*` esportate (l'identità git non è configurata) → `git switch <branch>` nel worktree e `git -C <root> switch main`. Se `origin/main` è avanzato: `git fetch` + `git merge origin/main` nel branch, risolvi i conflitti a mano, rilancia il gate. In Git Bash usa `MSYS_NO_PATHCONV=1` per `git show <ref>:<path>`.

## StudentOS architecture (the big picture)

**Offline-first, no backend database.** IndexedDB (via `idb`, schema in `src/lib/storage/db.ts`) is the source of truth. Zustand stores (`src/lib/state/*`) are in-memory mirrors with **write-through**: `StoreProvider` (`src/components/StoreProvider.tsx`) hydrates every store from IndexedDB on mount, renders immediately (cached data), then kicks a background sync. After any sync, the store re-reads from IndexedDB ("single source of truth"). Bump `DB_VERSION` and add an `upgrade()` branch for schema changes.

**Two strict data territories** (`src/lib/domain/types.ts`):
- **SYNCED** (public data: timetable, exams, news) — fetched by pluggable providers, treated as disposable caches replaced wholesale per source.
- **MANUAL** (libretto, notes, study tasks, focus sessions) — the user's own records; sync never writes here. Persisted in IndexedDB, mirrored by `src/lib/state/manual.ts` (a generic `createManualStore` factory).

**Optional online layer (Supabase) + onboarding gate** (`src/lib/supabase/*`, `src/components/{auth,onboarding}/*`). Entirely env-gated (`NEXT_PUBLIC_SUPABASE_URL`/`ANON_KEY` in `client.ts`); absent → the app is exactly the local-only build and `useAuth` sits in `"offline"`. Auth is **email+password** (`src/lib/supabase/auth.ts`: `signUpWithPassword`/`signInWithPassword`/`requestPasswordReset`/`updatePassword`), restricted to institutional inboxes (`isUniversityEmail`/`emailToAteneo`); the session lives in **cookies** via `@supabase/ssr` (`client.ts` `createBrowserClient` + `server.ts` `createServerClient`) and is refreshed on every request by `src/proxy.ts` (the Next 16 middleware, a no-op when the Supabase env is absent). `devLogin` fakes a session in dev (stripped from prod by the `NODE_ENV` check). `sync.ts` reconciles **once per sign-in**: cloud non-empty → cloud wins and replaces the local cache; cloud empty + local present → migrate local up; thereafter per-store subscriptions **push every mutation** best-effort (IndexedDB stays authoritative, UI never blocks on the network). The `profiles` row (`preset_id`, `programme`, `year_of_study`, `degree_plan`; RLS by `user_id`) is the **source of truth for "onboarded"**. **Account switch is a first-class event**: `StoreProvider`'s cloud effect is keyed on `userId` and diffed against `localStorage['studentos-uid']` (`UID_STORAGE_KEY`); a different uid (or `SIGNED_OUT`) runs `resetLocalData()` — wipes all manual territories + synced caches + the saved portal-credential secret + settings back to `DEFAULT_SETTINGS` — **before** hydrating, so no previous user's data shows or migrates upward. `useAuth.reconciled` gates the redirect so it never fires on half-applied settings. `FirstRunGate` sends any signed-in-but-unconfigured user hitting a gated route to `/onboarding` — completeness is judged on the cloud `profiles` row (`AuthCallback` reads it via `fetchProfile`), never on leftover local settings; `OnboardingFlow` walks ateneo → corso → anno and writes the profile. **Invariant: `resetLocalData` touches only local IndexedDB/stores, never cloud rows.** The cloud schema + RLS lives in `supabase/migrations/`: `0001_init.sql` (`profiles` + one identically-shaped `{user_id, id, data jsonb}` table per manual territory; every row guarded by `user_id = auth.uid()`), `0002_rate_limits.sql` (the distributed AI rate-limit counter, see the server-proxy security note) `0003_restrict_signup_domains.sql` (the Before-User-Created hook rejecting non-university signup domains — bound in the Dashboard and live since 2026-07-02; its domain list must be kept aligned with `emailToAteneo.ts` by hand), `0004_revoke_execute_handle_new_user.sql` (revokes EXECUTE on the SECURITY DEFINER `handle_new_user()` from anon/authenticated/public) and `0005_rls_initplan_wrap_auth_uid.sql` (rewrites the 5 owner RLS policies to the initplan-safe `(select auth.uid())` form). All are applied to the live project; `0004`/`0005` are backports (applied live on 2026-06-15, filed in the repo on 2026-07-04). Note the repo files use a sequential `000N_name.sql` convention while the live project's migration *tracking history* uses timestamp versions (`20260615…`, `20260701…`) with no entry for `0001_init` — the two naming schemes run on separate rails; these files are the schema documentation, not a `supabase db push` source synced 1:1 with tracking. The client stays the schema authority — the SQL stores each record as a JSONB blob, not column-per-field.

**Pluggable sync engine** (`src/lib/sync/`): everything flows through the `SyncProvider` interface (`provider.ts`, capabilities `"timetable" | "exams" | "news"`, zod-validated params). Adapters live in `adapters/` (`easyacademy` — drives all **18 live EasyAcademy atenei** via their JSON endpoints; `cineca-up` — Cineca University Planner, **dormant**: registered but no preset uses it until a real fixture confirms its contract, spec in `docs/superpowers/specs/2026-09-25-adapter-cineca-up-design.md`, live check + calendar census via `scripts/probe-cineca-up.ts`; `ical`; `wordpress-news`); `registry.ts` lists them; the SSRF guard for every server-side fetch is `src/lib/sync/validateUrl.ts` (host allowlist + `isPrivateIp` private/internal-IP rejection + `redirect:"manual"`), shared by the sync proxy and the insegnamenti discovery; `engine.ts` runs sources with per-source failure isolation; `universities/` holds presets (one file per live ateneo, e.g. `uniroma2.ts`, `unifi.ts`). The server entry is `src/app/api/sync/route.ts`; the browser side (`src/lib/storage/syncClient.ts` + `repo.ts`) atomically replaces each source's cache in one transaction and computes **change notices** via the content-diff engine (`src/lib/storage/diff.ts`). `defaultSyncRange` (in `syncClient.ts`) reaches **~15 weeks back** (`LOOKBACK_DAYS`) before "today" so a first sync started mid-semester isn't empty — the EasyAcademy timetable window begins at `from`. Synced entities use stable content-hash ids (`stableId`, cyrb53, in `sync/util.ts`) so they survive re-syncs and are diffable.

**University presets & live EasyAcademy sync** (`src/lib/sync/universities/`). `index.ts` builds `UNIVERSITY_PRESETS` = Tor Vergata (`uniroma2.ts`) + the other 17 live EasyAcademy atenei — one file each: `unica`, `unicampania`, `unife`, `unifi`, `unige`, `unina`, `unipg`, `unipr`, `unisa`, `unisalento`, `uniss`, `unistrasi`, `unitn`, `units`, `uniupo`, `unive`, `univpm` (`easyacademy-live.ts` is a thin aggregator importing one generated file each; `uniba.ts` is back in **manual mode** since 2026-09-25 — its combo 2026 is empty — with the 2025/26 wiring kept for restore) + the rest of Italy's public universities as **manual-mode** presets (`italian-atenei.ts`, `liveSources:false`). The live count + names are derived for the landing in `src/lib/liveAtenei.ts` (`LIVE_COUNT`, `LIVE_ATENEI`, `LIVE_PROGRAMME_COUNT`) so no number is hardcoded twice. **Whole-ateneo, not just Informatica:** each live preset exposes its *entire* verifiable catalogue (1484 verified live degrees across the 18 atenei on 2026-09-25 — `LIVE_PROGRAMME_COUNT`) through `UniversityPreset.livePrograms: LiveProgram[]` (`provider.ts`) — one `{programme, sources}` per degree, the `sources` built by the shared `degreeSources(baseUrl, anno, slug, scuola, years, exams)` helper in `easystaff.ts` and **namespaced** (`<slug>-orario-anno-N` / `<slug>-esami-anno-N`) so two degrees of one ateneo never share a cache key. `liveProgramFor(preset, programme)` (case-insensitive, `index.ts`) resolves the onboarded programme → its sources; `settings.enabledSources()` returns them, or **`[]` (= manual mode)** when the chosen programme isn't live. Per-year `{corso, anno2[]}` selectors drive timetable (`grid_call.php`) + exams (`test_call.php`); the 2025/26 ordinamento reform splits trienni across two `corso` codes (year-1 vs year-2/3), so each year carries its own; some atenei publish timetable only (`exams:false`). **Codes are captured, never invented**: the cascade `combo.php?sw=ec_&aa=<YEAR>&page=corsi` returns `elenco_corsi` (each course's `scuola`, `valore`=corso, `elenco_anni[].valore`=anno2). **Hard rule: only ship a degree as live after POSTing the real endpoints and seeing `celle`/`Appelli` come back** — wrong data is worse than none; an unverifiable corso stays manual. `ateneo-courses.ts` holds each ateneo's **manual-only** catalogue; `OnboardingFlow`'s `programmesOf` prepends the live degree names, tagging the verified ones "sync live" and the rest "manuale". The old single-programme `easyAcademyPreset()` builder was removed (superseded by `livePrograms`). Census of Italian timetable systems (EasyAcademy, Cineca UP, GOMP, Esse3, in-house) + integration status lives in `_coverage.md`, with per-ateneo `_<id>_coverage.md` listing every corso and its verified live/manual status. **Each September, bump every preset's `anno` and re-verify its codes** (universities renumber `corso`/`anno2` per cohort).

**Pure domain logic, tested in isolation from React.** `src/lib/domain/` holds framework-free, deterministic modules — clocks/timezones are passed in as arguments — most with a matching `tests/*.test.ts`: `urgency`, `libretto` (weighted average, lode=30, pass/excluded skip), `projection`, `week` (timetable lane layout), `booking`, `calendar`, `notes` (search), `focus`, `academicYear`, `csv` (libretto import), `delphiPdf` (parses the reflowed "Esami verbalizzati" Delphi PDF text — client-side via pdfjs, zero upload), plus the newer ones: `achievements` + `trophyView` + `celebrations` (the Libretto trophy/achievement engine), `detectAlerts` + `alerts` (the smart-alerts engine — see the alerts subsystem below), `examStatus` (whether an exam call is still relevant vs. already passed), `sources` (`matchesYear`/`yearOfSource` over the `…-anno-N` sourceId suffix), `emailToAteneo`, `ical`, `pdfImport` + `pdfLayout` (generic PDF text → libretto rows, server-assisted). `src/lib/esse3/parse.ts` and `src/lib/sync/delphi/parse.ts` are likewise pure + tested. `src/lib/assistente.ts` holds the shared types + the pure `buildSystemPrompt`. Prefer adding logic here (pure + testable) over inside components.

**Design system is token-driven.** Colors/radii/fonts are CSS variables in `src/app/globals.css` `@theme`. The Tailwind token *names* (`night-*`, `ink`, `line`, `signal`, …) are legacy; their **values are remapped to immersive vars** (`var(--bg)`, `var(--surface)`, `var(--ink)`, `var(--signal)`, …) defined in two blocks above `@theme`: `[data-theme="dark"]` (the default) and `[data-theme="light"]`. So a reskin = editing those var blocks + a few primitives (`src/components/primitives/`), **never** sweeping every component. Fonts: **Bricolage Grotesque** for display (`--font-display`, used by `h1`–`h4`) + **Inter** for body, both loaded in `layout.tsx` via `next/font/google`; `--font-mono` is still Inter + tabular-nums (no real monospace face). Keep contrast AA in both themes; UI copy is **Italian-first**.

**Theming + motion (immersive layer).** Theme is an attribute on `<html data-theme>`, set before first paint by an inline `<head>` script in `layout.tsx` (no FOUC) and toggled via `ThemeToggle` → `src/lib/hooks/useTheme.ts` (a `useSyncExternalStore` over `documentElement.dataset.theme` + `localStorage['studentos-theme']`). The drifting **aurora** is the `.atmosphere` div (fixed, `z-index:-1`) in `layout.tsx`; glass/lift/reveal/grad-text and all keyframes live in `globals.css`. **Animations are pure CSS keyframes** (framer-motion is NOT installed) plus minimal JS: `CountUp` (imperative `textContent` tween, SSR-safe), `RevealManager` (IntersectionObserver adds `.in` to `.reveal` on scroll), `useScrolled` (navbar frost). A global `prefers-reduced-motion` block neutralizes them. Per the Next caveat, hook stores use `useSyncExternalStore`, and **server components must not pass functions to client components** (e.g. `CountUp` takes serializable `decimals`/`suffix`, not a `format` fn).

**Libretto "synced from ateneo" import** (`src/lib/sync/delphi/*`, `src/app/api/sync-delphi/route.ts`, `src/components/libretto/{ImportDelphiPdf,DelphiConnect}.tsx`). The **live** path is the client-side **Delphi PDF import** (pdfjs in the browser, zero upload — see `domain/delphiPdf.ts`). An optional server-side **credential scrape** also exists: `POST /api/sync-delphi` logs into delphi.uniroma2.it server-side and returns parsed `LibrettoEntry[]` (credentials used once as local consts, then dropped — never logged/stored/cached). Synced rows are tagged `source: "delphi"` (the "synced from ateneo" bucket) vs `"manual"`; `replaceDelphiLibretto` swaps only the synced bucket atomically, leaving manual entries untouched. The `DelphiConnect` credential UI is intentionally disabled ("prossimamente"). **The old SAML/SSO + Esse3 career-sync subsystem was removed** (Fase 1 of the security audit): `src/lib/saml/`, `src/app/api/saml/*`, `esse3/client.ts`, `state/delphi.ts` are gone, and `@node-saml/node-saml` is out of `package.json`. The orphan `esse3/parse.ts` parser (never wired, 0 callers) was deleted together with its test.

**Nav (7 voci):** Panoramica · Orario · Insegnamenti · Appelli · Libretto · Note · Focus, with **Impostazioni** as a gear icon in the right cluster and **Assistente** as a floating bubble (`AssistantBubble` wrapping a compact `AssistantChat`); Calendario is NOT in the bar. The mobile bottom tab bar uses the same names abbreviated only where they don't fit (`short` in `AppNav.tsx`: "Home" for Panoramica, "Materie" for Insegnamenti — never a different vocabulary). Libretto trophies UI: `CareerStrip` / `TrophyGrid` (two-step delete: arm 4s, Esc disarms) / `TrophyShowcase`, deep-link `/libretto#trofei`.

**API routes** (all server proxies, `runtime = "nodejs"`, `dynamic = "force-dynamic"`, structured logger in `src/lib/api/logger.ts`):
- `POST /api/sync` — the EasyAcademy/iCal/news sync engine entry.
- `POST /api/sync-delphi` — the optional Delphi credential scrape (disabled UI).
- `POST /api/assistente` — server-side proxy to **Groq** (`llama-3.3-70b-versatile`, env `GROQ_API_KEY`/`GROQ_MODEL`), streams SSE back as a plain-text token stream; the client-supplied `context` is clamped (max exams/lessons/field length) so a hostile same-origin caller can't inflate the prompt into a cost vector.

- `POST /api/alerts` — server-side parity surface for the pure `detectAlerts` (the browser posts its synced+manual snapshot, gets back `Alert[]`; nothing persisted — there is no server IndexedDB).
- `POST /api/insegnamenti/sync` — manifesto-URL discovery + raw-HTML fetch for the insegnamenti feature (parse + persist happen client-side).
- `GET /api/health`.

**Server-proxy security (the security-audit hardening lives here).** Two shared guards under `src/lib/api/`:
- `guard.ts` (`guardPost`) — same-origin/same-site check + a **two-layer rate limit**: an HMAC-signed fixed-window cookie (`srl_<route>`, correct *cross-instance* on serverless, secret = `RATE_LIMIT_SECRET` ↦ `GROQ_API_KEY`, one-way digest, no secret ever exposed) backed by the legacy per-IP in-memory window (`x-forwarded-for` uses the last/trusted hop and **fails closed** when the IP is indeterminate). No mandatory auth — that would break the no-account build.
- `aiGuard.ts` (`guardAiPost`, used by `/api/assistente` + `/api/import-pdf`) — adds three layers on top: (A) auth required *when Supabase is configured*, (B) a global per-minute **circuit-breaker** (`AI_CB_LIMIT`, default 60), (C) a global per-UTC-day **spend cap** (`AI_DAILY_CAP`, default 500). The global counters are **distributed** via `distributedRateLimit.ts` (Supabase table `rate_limits` + SECURITY DEFINER `rate_limit_hit`, migration `0002`, RLS deny-by-default) and degrade to the legacy in-memory per-instance window when Supabase is absent or unreachable (fail-open toward the backstop, no Redis — no new dependency allowed).
The SSRF guard for outbound fetches is `src/lib/sync/validateUrl.ts` (`isPrivateIp` etc.), reused by the sync proxy and `insegnamenti/discovery.ts`.

**Insegnamenti (piano di studi) subsystem** (`src/lib/insegnamenti/` + `src/lib/state/insegnamenti.ts` + `src/types/insegnamenti.ts`, page `/insegnamenti`). Discovers a degree's "manifesto degli studi" web page and scrapes its insegnamenti. Split server/client by necessity: `discovery.ts` (server, the sole network egress — curated host allowlist + private-IP rejection + `redirect:"manual"`) finds + fetches the raw HTML; the client (`sync.ts` + `parser.ts`) parses with `DOMParser` (absent in Node) and writes to IndexedDB. **Honesty rule applies**: most Italian catalogues are client-rendered SPAs with no static CFU table, so discovery validates the HTML (`<table>` + "CFU"/"crediti") and returns `null` → the degree falls back to **manual** entry rather than shipping garbage. Synced rows carry `inserito_manualmente === false`; manual ones `true`. This store is **not** hydrated by `StoreProvider` — `/insegnamenti` loads it on mount once the onboarded ateneo/corso is known.

**Assistente (AI chat)** (`/assistente` page + `AssistantBubble`/`AssistantChat`, `src/lib/assistente.ts`, `POST /api/assistente`). The client gathers the live student context from the stores (already locale-formatted), the pure `buildSystemPrompt` turns it into the Italian system prompt, the route streams Groq's reply token-by-token. `AssistantBubble` lazy-loads `AssistantChat` via `next/dynamic` (`ssr:false`) so react-markdown isn't in every page's initial bundle.

**Routes:** `/` (public **landing** page — hero with the animated `S→tudent🛟S` wordmark, feature cards, "Come funziona", stats, footer; no login), `/panoramica` (the predictive bento **dashboard** — instruments media/CFU/projection read the libretto store reactively, live), `/orario` (CSS-Grid week view, with year + per-course filters), `/appelli` (month calendar + exam cards, with year + per-course filters), `/libretto` (manual entry + CSV import + Delphi PDF import + career instruments + "Obiettivo laurea" goal card), `/note` (Markdown+KaTeX+code editor with full-text search), `/focus` (pomodoro + kanban), `/insegnamenti` (the corso's piano di studi — synced manifesto rows + manual ones, see the subsystem note), `/assistente` (the full-page AI chat; also reachable as the floating bubble everywhere except `/`), `/calendario` (month/agenda view; **not** in the nav bar), `/impostazioni` (settings; reached via the gear icon), `/design` (component gallery), `/privacy` (the public informativa, a server component: every claim mirrors a real data flow in the code — when a feature starts sending data off-device, update it **and** add a point-of-use notice like the ones in `AssistantChat` / `ImportPdfButton`), `/login` + `/auth/callback` + `/auth/reset` (optional email+password sign-in, with sign-up confirm and password recovery), `/onboarding` (the mandatory ateneo/corso/anno setup — `FirstRunGate` redirects any unconfigured signed-in user here). `/orario` and `/appelli` share the same filter primitives — `<YearFilter>` (`components/YearFilter.tsx`, chips Tutti/1°/2°/3°, default "Tutti") + `<CoursePicker>` (`components/timetable/CoursePicker.tsx`) over `domain/sources.ts`'s `matchesYear`/`yearOfSource`, which read the `…-anno-N` suffix of each event's `sourceId` (the namespacing `degreeSources` emits). `template.tsx` wraps every page for the per-navigation entrance animation; the `Wordmark` (lucide `LifeBuoy` as the "O") is the brand mark in navbar + footer.
